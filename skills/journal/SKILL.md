# Journal — 每日反思日誌

把「今天過得怎樣」變成 3 分鐘的引導對話，寫成日誌存進記憶系統。
使用者不用開檔案、不用想格式，口語回答即可。

## 觸發時先做的事

1. 找出最近一篇日誌（`private/memory/daily/` 內含日誌段落的最新檔案）。
2. 若其中有未勾選的「明日三件事」，先回顧：

   > 上次你列了這三件事：…。今天完成了哪些？

   使用者的回答併入今天的 Q1，不重問。
3. 沒有先前日誌就直接開始，不用說明機制。

## 五題引導（逐題問，每次只問一題）

| # | 問題 | 目的 |
|---|---|---|
| Q1 | 今天做了哪些事？發生了什麼？ | 事實——從最容易回答的開始 |
| Q2 | 有什麼順利或讓你意外的時刻？ | 亮點——不只記挫折 |
| Q3 | 哪裡卡住了？下次可以怎麼做更好？ | 反思——卡關紀錄是最有價值的資產 |
| Q4 | 明天「你能控制」的一個小改進是什麼？ | 可控改變——要具體行為，不收空泛目標 |
| Q5 | 明天最重要的三件事？ | 待辦——上限三件，避免清單膨脹 |

規則：

- 任何一題使用者說「跳過」就跳過，寫了一半也比沒寫有價值。
- 使用者一次回答涵蓋多題時直接吸收，不重問。
- 不逼問、不評價使用者的內容；追問最多一次且只為了具體化 Q4／Q5。
- 若本 Session 的工作內容 AI 已經知道（今天一起做過的事），Q1 改為
  「今天我們做了 X、Y、Z，除此之外還有什麼？」——不要明知故問。

## 寫入位置

**日誌本體**：`private/memory/daily/YYYY-MM-DD.md`（今天日期）。
該檔已存在（session 紀錄）時，在檔尾追加 `## 日誌` 段落，不覆蓋既有內容。

```markdown
## 日誌

### 今天
（Q1＋Q2 整理成 3–6 句，保留使用者用語，不美化）

### 反思與改進
（Q3＋Q4；卡關處標記 `#卡關` 方便日後檢索）

### 明日三件事
- [ ] …
- [ ] …
- [ ] …
```

**閉環**：把「明日三件事」同步寫入 `private/memory/active-context.md` 的
下一步區塊（取代由前次日誌寫入的舊待辦，不動其他內容）——AIOS 的續作
機制會在明天任何新對話載入它，提醒不依賴本 Skill 被再次觸發。

**記憶路由**：反思中出現的偏好、踩坑或重要決定，依根入口的記憶路由處理
（觀察性內容進 inbox 當候選；使用者明確要求記住的才直接寫入正式位置）。
不要因為寫日誌就自動改動 Context。

## 完成後

顯示日誌全文讓使用者確認，確認後存檔。之後只回一句話收尾（例如提醒
明天第一件事），不要長篇總結。

## 回顧模式

使用者說「看上週的日記」「這個月學到什麼」時：讀 `private/memory/daily/`
對應日期範圍的日誌段落，整理成摘要（完成的事、反覆出現的卡關、改進是否
落實）。純唯讀，不寫檔。
